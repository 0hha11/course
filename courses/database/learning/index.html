数据库原理与应用学习内容

详细的课程知识点和学习指南

课程概述

数据库原理与应用课程是商务数据分析与应用专业的核心课程之一，旨在帮助学生掌握数据库的基本原理、SQL语言以及数据库设计和管理的实践技能， 为后续的数据分析和数据处理课程打下坚实的基础。

通过本课程的学习，学生将能够：

  • 掌握数据库的基本概念和原理
  • 学习SQL语言的基本语法和应用
  • 掌握数据库设计的方法和技巧
  • 学习数据库管理和维护的基本操作
  • 能够使用数据库工具解决实际业务问题

第1章：数据库概述

1.1 数据库的概念

数据库是指长期存储在计算机内的、有组织的、可共享的数据集合。数据库中的数据按一定的数据模型组织、描述和存储，具有较小的冗余度、较高的数据独立性和易扩展性，并可为各种用户共享。

1.2 数据库的发展历程

  1. 人工管理阶段：20世纪50年代中期以前，数据由应用程序管理，没有专门的数据库管理系统
  2. 文件系统阶段：20世纪50年代后期至60年代中期，数据以文件形式存储，由文件系统管理
  3. 数据库系统阶段：20世纪60年代后期至今，数据由数据库管理系统（DBMS）统一管理

1.3 数据库的分类

  • 按数据模型分类：关系型数据库、NoSQL数据库、NewSQL数据库等
  • 按应用领域分类：商务数据库、科学数据库、多媒体数据库等
  • 按部署方式分类：本地数据库、云端数据库、分布式数据库等

1.4 数据库管理系统（DBMS）

数据库管理系统是位于用户与操作系统之间的一层数据管理软件，是基础软件，也是一种关键应用软件。

  • 主要功能：数据定义、数据操作、数据库运行管理、数据库建立和维护
  • 常见DBMS：MySQL、Oracle、SQL Server、PostgreSQL、MongoDB等

第2章：数据模型

2.1 数据模型的概念

数据模型是对现实世界数据特征的抽象，是数据库系统的核心和基础。数据模型通常由数据结构、数据操作和完整性约束三部分组成。

2.2 实体-关系模型（E-R模型）

E-R模型是一种概念数据模型，用于描述现实世界中的实体及其之间的关系。

  • 实体：现实世界中可区分的事物，如学生、课程、教师等
  • 属性：实体的特征，如学生的学号、姓名、年龄等
  • 关系：实体之间的联系，如学生选修课程
  • 关系类型：一对一、一对多、多对多

2.3 层次模型

层次模型是一种树形结构的数据模型，以树状结构表示实体及其之间的关系。

  • 有且只有一个根节点
  • 根节点以外的其他节点有且只有一个父节点
  • 层次分明，查询效率高
  • 不适合表示多对多关系

2.4 网状模型

网状模型是一种网络结构的数据模型，以图结构表示实体及其之间的关系。

  • 允许一个节点有多个父节点
  • 可以表示多对多关系
  • 结构复杂，不易管理

2.5 关系模型

关系模型是目前最流行的数据模型，以二维表格表示实体及其之间的关系。

  • 关系：对应二维表格
  • 元组：对应表格中的一行
  • 属性：对应表格中的一列
  • 域：属性的取值范围
  • 关系模式：对关系的描述，如学生(学号, 姓名, 年龄, 性别)

第3章：SQL语言基础

3.1 SQL语言概述

SQL（Structured Query Language）是结构化查询语言，是关系型数据库的标准语言。SQL语言具有以下特点：

  • 综合统一
  • 高度非过程化
  • 面向集合的操作方式
  • 语言简洁，易学易用
  • 支持多种数据库系统

3.2 数据定义语言（DDL）

DDL用于定义数据库结构，包括创建、修改和删除数据库对象。 

-- 创建数据库
CREATE DATABASE school;

-- 使用数据库
USE school;

-- 创建表
CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    age INT,
    gender VARCHAR(10),
    major VARCHAR(50)
);

-- 修改表
ALTER TABLE student ADD COLUMN email VARCHAR(100);
ALTER TABLE student MODIFY COLUMN age INT NOT NULL;

-- 删除表
DROP TABLE student;

-- 删除数据库
DROP DATABASE school;

3.3 数据操作语言（DML）

DML用于操作数据库中的数据，包括插入、更新和删除数据。 

-- 插入数据
INSERT INTO student (id, name, age, gender, major) VALUES
(1, '张三', 20, '男', '计算机科学与技术'),
(2, '李四', 21, '女', '软件工程'),
(3, '王五', 19, '男', '数据科学与大数据技术');

-- 更新数据
UPDATE student SET age = 22 WHERE id = 1;
UPDATE student SET major = '人工智能' WHERE gender = '女';

-- 删除数据
DELETE FROM student WHERE id = 3;
DELETE FROM student WHERE age > 20;

3.4 数据查询语言（DQL）

DQL用于查询数据库中的数据，是SQL中最常用的部分。 

-- 查询所有数据
SELECT * FROM student;

-- 查询特定列
SELECT id, name, major FROM student;

-- 带条件查询
SELECT * FROM student WHERE age > 20;
SELECT * FROM student WHERE gender = '男' AND major = '计算机科学与技术';

-- 排序查询
SELECT * FROM student ORDER BY age DESC;
SELECT * FROM student ORDER BY major ASC, age DESC;

-- 限制查询结果
SELECT * FROM student LIMIT 2;
SELECT * FROM student LIMIT 1, 2; -- 从第2条开始，取2条

第4章：高级SQL查询

4.1 复杂查询

-- 使用DISTINCT去重
SELECT DISTINCT major FROM student;

-- 使用LIKE模糊查询
SELECT * FROM student WHERE name LIKE '张%';
SELECT * FROM student WHERE name LIKE '%三%';

-- 使用IN查询
SELECT * FROM student WHERE major IN ('计算机科学与技术', '软件工程');

-- 使用BETWEEN查询
SELECT * FROM student WHERE age BETWEEN 19 AND 21;

4.2 连接查询

连接查询用于查询多个表中的数据，包括内连接、外连接和交叉连接。 

-- 创建课程表
CREATE TABLE course (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    credits INT
);

-- 创建选课表
CREATE TABLE enrollment (
    student_id INT,
    course_id INT,
    grade INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES student(id),
    FOREIGN KEY (course_id) REFERENCES course(id)
);

-- 内连接
SELECT s.id, s.name, c.name AS course_name, e.grade
FROM student s
INNER JOIN enrollment e ON s.id = e.student_id
INNER JOIN course c ON e.course_id = c.id;

-- 左外连接
SELECT s.id, s.name, c.name AS course_name, e.grade
FROM student s
LEFT JOIN enrollment e ON s.id = e.student_id
LEFT JOIN course c ON e.course_id = c.id;

-- 右外连接
SELECT s.id, s.name, c.name AS course_name, e.grade
FROM student s
RIGHT JOIN enrollment e ON s.id = e.student_id
RIGHT JOIN course c ON e.course_id = c.id;

4.3 子查询

子查询是嵌套在其他查询中的查询，用于更复杂的查询需求。 

-- 子查询作为条件
SELECT * FROM student WHERE age > (SELECT AVG(age) FROM student);

-- 子查询作为结果集
SELECT * FROM (SELECT * FROM student WHERE gender = '男') AS male_students;

--  EXISTS子查询
SELECT * FROM student s WHERE EXISTS (SELECT * FROM enrollment e WHERE e.student_id = s.id);

-- IN子查询
SELECT * FROM student WHERE id IN (SELECT student_id FROM enrollment WHERE grade > 80);

4.4 分组和聚合

分组和聚合用于对数据进行统计分析。 

-- 分组查询
SELECT gender, COUNT(*) AS count FROM student GROUP BY gender;
SELECT major, AVG(age) AS avg_age FROM student GROUP BY major;

-- 带条件的分组查询
SELECT major, COUNT(*) AS count FROM student GROUP BY major HAVING COUNT(*) > 1;

-- 常用聚合函数
SELECT COUNT(*) AS total_students FROM student;
SELECT AVG(age) AS avg_age FROM student;
SELECT MAX(age) AS max_age, MIN(age) AS min_age FROM student;
SELECT SUM(age) AS total_age FROM student;

4.5 视图

视图是虚拟表，是从一个或多个表中导出的表。 

-- 创建视图
CREATE VIEW student_course AS
SELECT s.id, s.name, c.name AS course_name, e.grade
FROM student s
INNER JOIN enrollment e ON s.id = e.student_id
INNER JOIN course c ON e.course_id = c.id;

-- 查询视图
SELECT * FROM student_course;

-- 修改视图
CREATE OR REPLACE VIEW student_course AS
SELECT s.id, s.name, s.gender, c.name AS course_name, e.grade
FROM student s
INNER JOIN enrollment e ON s.id = e.student_id
INNER JOIN course c ON e.course_id = c.id;

-- 删除视图
DROP VIEW student_course;

4.6 存储过程和函数

存储过程和函数是预编译的SQL语句集合，用于实现复杂的业务逻辑。 

-- 创建存储过程
DELIMITER //
CREATE PROCEDURE get_students_by_major(IN major_name VARCHAR(50))
BEGIN
    SELECT * FROM student WHERE major = major_name;
END //
DELIMITER ;

-- 调用存储过程
CALL get_students_by_major('计算机科学与技术');

-- 创建函数
DELIMITER //
CREATE FUNCTION get_student_count_by_gender(gender_param VARCHAR(10)) RETURNS INT
BEGIN
    DECLARE count INT;
    SELECT COUNT(*) INTO count FROM student WHERE gender = gender_param;
    RETURN count;
END //
DELIMITER ;

-- 调用函数
SELECT get_student_count_by_gender('男') AS male_count;

第5章：数据库设计

5.1 数据库设计的原则和方法

数据库设计是指根据用户需求，设计数据库的结构和存储方式。数据库设计的基本原则包括：

  • 数据独立性
  • 数据完整性
  • 数据一致性
  • 数据安全性
  • 性能优化

5.2 需求分析

需求分析是数据库设计的第一步，用于了解用户的业务需求和数据需求。

  • 收集用户需求
  • 分析业务流程
  • 确定数据范围
  • 识别实体和关系

5.3 概念设计

概念设计是数据库设计的第二步，用于构建E-R模型，描述实体及其之间的关系。 

-- 实体：学生(Student)
-- 属性：学号(id)、姓名(name)、年龄(age)、性别(gender)、专业(major)

-- 实体：课程(Course)
-- 属性：课程号(id)、课程名(name)、学分(credits)

-- 实体：教师(Teacher)
-- 属性：教师号(id)、姓名(name)、性别(gender)、职称(title)

-- 关系：学生选修课程(Enrollment)
-- 属性：学号(student_id)、课程号(course_id)、成绩(grade)

-- 关系：教师教授课程(Teach)
-- 属性：教师号(teacher_id)、课程号(course_id)

5.4 逻辑设计

逻辑设计是数据库设计的第三步，用于将E-R模型转换为关系模型，设计表结构。 

-- 学生表
CREATE TABLE Student (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    age INT,
    gender VARCHAR(10),
    major VARCHAR(50)
);

-- 课程表
CREATE TABLE Course (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    credits INT
);

-- 教师表
CREATE TABLE Teacher (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    gender VARCHAR(10),
    title VARCHAR(50)
);

-- 选课表
CREATE TABLE Enrollment (
    student_id INT,
    course_id INT,
    grade INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES Student(id),
    FOREIGN KEY (course_id) REFERENCES Course(id)
);

-- 授课表
CREATE TABLE Teach (
    teacher_id INT,
    course_id INT,
    PRIMARY KEY (teacher_id, course_id),
    FOREIGN KEY (teacher_id) REFERENCES Teacher(id),
    FOREIGN KEY (course_id) REFERENCES Course(id)
);

5.5 物理设计

物理设计是数据库设计的第四步，用于确定数据库的存储结构和访问方法。

  • 选择存储引擎
  • 设计索引
  • 优化表结构
  • 配置数据库参数

第6章：数据库完整性

6.1 实体完整性

实体完整性是指主键的值不能为空且唯一，用于保证实体的唯一性。 

-- 主键约束
CREATE TABLE student (
    id INT PRIMARY KEY,  -- 主键约束
    name VARCHAR(50) NOT NULL,
    age INT,
    gender VARCHAR(10)
);

-- 唯一约束
CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,  -- 唯一约束
    age INT,
    gender VARCHAR(10)
);

6.2 参照完整性

参照完整性是指外键的值必须是引用表中主键的有效值或空值，用于保证表之间的关联关系。 

-- 外键约束
CREATE TABLE enrollment (
    student_id INT,
    course_id INT,
    grade INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES student(id) ON DELETE CASCADE,
    FOREIGN KEY (course_id) REFERENCES course(id) ON UPDATE CASCADE
);

-- ON DELETE CASCADE：当主表记录删除时，从表相关记录也删除
-- ON UPDATE CASCADE：当主表主键更新时，从表外键也更新
-- ON DELETE SET NULL：当主表记录删除时，从表外键设为NULL
-- ON DELETE RESTRICT：当主表记录有从表引用时，禁止删除

6.3 用户定义完整性

用户定义完整性是指根据用户需求定义的约束，用于保证数据的有效性。 

-- 非空约束
CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,  -- 非空约束
    age INT,
    gender VARCHAR(10)
);

-- 检查约束
CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    age INT CHECK (age > 0 AND age < 100),  -- 检查约束
    gender VARCHAR(10) CHECK (gender IN ('男', '女')),  -- 检查约束
    email VARCHAR(100)
);

-- 默认值约束
CREATE TABLE student (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    age INT DEFAULT 18,  -- 默认值约束
    gender VARCHAR(10) DEFAULT '男',  -- 默认值约束
    email VARCHAR(100)
);

第7章：数据库安全

7.1 数据库安全的概念

数据库安全是指保护数据库免受未授权访问、修改、破坏或泄露的措施。

  • 保密性：保护数据不被未授权访问
  • 完整性：保证数据的正确性和一致性
  • 可用性：确保数据库服务的正常运行
  • 可控性：控制对数据的访问和操作

7.2 访问控制

访问控制是指限制用户对数据库的访问权限，包括认证和授权。 

-- 创建用户
CREATE USER 'user1'@'localhost' IDENTIFIED BY 'password123';
CREATE USER 'user2'@'%' IDENTIFIED BY 'password456';

-- 授权
GRANT SELECT, INSERT, UPDATE ON school.student TO 'user1'@'localhost';
GRANT ALL PRIVILEGES ON school.* TO 'user2'@'%';

-- 撤销权限
REVOKE UPDATE ON school.student FROM 'user1'@'localhost';

-- 查看权限
SHOW GRANTS FOR 'user1'@'localhost';

-- 删除用户
DROP USER 'user1'@'localhost';

7.3 用户权限管理

用户权限管理是指管理用户的角色和权限，确保用户只能访问和操作其授权范围内的数据。 

-- 创建角色
CREATE ROLE 'student_role';
CREATE ROLE 'teacher_role';

-- 给角色授权
GRANT SELECT ON school.student TO 'student_role';
GRANT SELECT, INSERT, UPDATE ON school.course TO 'teacher_role';

-- 将角色授予用户
GRANT 'student_role' TO 'user1'@'localhost';
GRANT 'teacher_role' TO 'user2'@'%';

-- 激活角色
SET DEFAULT ROLE ALL TO 'user1'@'localhost';
SET DEFAULT ROLE ALL TO 'user2'@'%';

7.4 数据加密

数据加密是指对敏感数据进行加密存储，防止数据泄露。

  • 传输加密：使用SSL/TLS加密数据传输
  • 存储加密：对敏感数据进行加密存储
  • 应用层加密：在应用程序中对数据进行加密

7.5 审计

审计是指记录和监控数据库的访问和操作，用于追踪和分析数据库活动。 

-- 启用审计日志
SET GLOBAL general_log = 'ON';
SET GLOBAL general_log_file = '/var/log/mysql/general.log';

-- 查看审计日志
SELECT * FROM mysql.general_log;

-- 启用二进制日志
SET GLOBAL log_bin = 'ON';
SET GLOBAL binlog_format = 'ROW';

-- 查看二进制日志
SHOW BINARY LOGS;
PURGE BINARY LOGS BEFORE '2023-12-31 23:59:59';

INNER JOIN enrollment e ON s.id = e.student_id
INNER JOIN course c ON e.course_id = c.id;

-- 查询教师授课情况
SELECT t.teacher_id, t.name, c.name AS course_name, tch.semester, tch.year
FROM teacher t
INNER JOIN teach tch ON t.id = tch.teacher_id
INNER JOIN course c ON tch.course_id = c.id;

-- 查询课程平均成绩
SELECT c.name AS course_name, AVG(e.grade) AS avg_grade
FROM course c
INNER JOIN enrollment e ON c.id = e.course_id
WHERE e.grade IS NOT NULL
GROUP BY c.id, c.name;

-- 查询学生平均成绩
SELECT s.student_id, s.name, AVG(e.grade) AS avg_grade
FROM student s
INNER JOIN enrollment e ON s.id = e.student_id
WHERE e.grade IS NOT NULL
GROUP BY s.id, s.student_id, s.name
ORDER BY avg_grade DESC;

8.2 案例二：电商系统数据库设计

设计一个电商系统的数据库，包括用户、商品、订单、支付等信息。 

-- 创建数据库
CREATE DATABASE e-commerce;
USE e-commerce;

-- 创建用户表
CREATE TABLE user (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(100) NOT NULL,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    phone VARCHAR(20) UNIQUE NOT NULL,
    address TEXT,
    register_time DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 创建商品分类表
CREATE TABLE category (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    description TEXT
);

-- 创建商品表
CREATE TABLE product (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    price DECIMAL(10, 2) NOT NULL,
    stock INT NOT NULL,
    category_id INT,
    image_url VARCHAR(255),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (category_id) REFERENCES category(id) ON DELETE SET NULL
);

-- 创建订单表
CREATE TABLE order_ (
    id INT PRIMARY KEY AUTO_INCREMENT,
    order_id VARCHAR(50) UNIQUE NOT NULL,
    user_id INT,
    total_amount DECIMAL(10, 2) NOT NULL,
    status VARCHAR(20) NOT NULL, -- 待支付、已支付、已发货、已完成、已取消
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    pay_time DATETIME,
    ship_time DATETIME,
    complete_time DATETIME,
    FOREIGN KEY (user_id) REFERENCES user(id) ON DELETE CASCADE
);

-- 创建订单商品表
CREATE TABLE order_item (
    id INT PRIMARY KEY AUTO_INCREMENT,
    order_id INT,
    product_id INT,
    quantity INT NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    FOREIGN KEY (order_id) REFERENCES order_(id) ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES product(id) ON DELETE CASCADE
);

-- 创建支付表
CREATE TABLE payment (
    id INT PRIMARY KEY AUTO_INCREMENT,
    order_id INT,
    payment_method VARCHAR(50) NOT NULL, -- 支付宝、微信支付、银行卡等
    payment_status VARCHAR(20) NOT NULL, -- 待支付、已支付、支付失败
    amount DECIMAL(10, 2) NOT NULL,
    transaction_id VARCHAR(100),
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    pay_time DATETIME,
    FOREIGN KEY (order_id) REFERENCES order_(id) ON DELETE CASCADE
);
